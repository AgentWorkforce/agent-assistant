## Summary
This trajectory set documents the multi-month build-out of `agent-assistant` (formerly `relay-agent-assistant`/`@relay-assistant/*`) as a provider-neutral SDK extracted from Sage v2 and the broader Workforce program. Work proceeded through staged Agent Relay supervisor/DAG workflows: initial spec authorship and reconciliation (canonical specs, v1 workflow backlog, sectioning), v1 package implementation (`@agent-assistant/core`, `sessions`, `surfaces`, `connectivity`, `coordination`, `routing`, `memory`, `traits`, `vfs`, `proactive`, `telemetry`, `harness`), hardening passes against review verdicts, and the SDK-wide rename from `relay-assistant` to `agent-assistant`. The most recent arc (May 4–8, 2026) focused on the Sage v2 substrate extraction: a nested subagent runner in `packages/harness`, a runtime budget policy, telemetry vocabulary (`packages/telemetry`), an eval substrate (`@agent-assistant/telemetry/evals` + `@agent-assistant/evals` workspace package), and an insight envelope/reader in `packages/vfs/src/insight/`. The substrate work landed across two main PRs: a large multi-slice extraction (PR #86, merged) and a follow-up first-slice-only PR (#87) that re-introduced the nested subagent runner with full peer review (`fresh-eyes-codex`, `peer-review-claude`) and 80-to-100 validation. CI broke on the larger PR due to premature runtime-policy export surface, then again on review feedback from CodeRabbit around child-trace fallback ordering (parentTraceId vs childTraceId) and a string-keyed child counter map that could leak parent turn entries in long-lived harnesses. Both were addressed via narrow follow-up commits (63fddb0, 1cd3e23) rather than amends. Earlier sessions also added Sage feature-promotion primitives (A2A card/RPC route helpers in webhook-runtime, public GitHub fetcher/source-navigation, bounded GitHub harness tool registry) and reusable memory helpers (`@agent-assistant/memory`). The consistent operational pattern is: Claude lead writes a bounded scope/plan doc under `docs/architecture/`, Codex executor implements one slice at a time against `docs/specs/`, targeted package tests gate each slice, then fresh-eyes review + 80-to-100 validation + self-reflection docs close the loop before commit/PR. The user explicitly authors and dry-runs workflows but does not run them — execution is the user's responsibility per saved memory.

## Conventions Established
- **Per-slice DAG: lead-plan → executor (codex) → targeted tests → executor-self-reflection → fresh-eyes review (codex) → peer-review (claude) → 80-to-100 validation → validation-self-reflection**: Bounded slices with verification-based completion catch regressions early and keep PRs reviewable. (scope: All v1 package and substrate workflows under `docs/workflows/`.)
- **Plans live in `docs/architecture/<topic>-implementation-plan.md` (or `-scope.md`); specs in `docs/specs/v1-<topic>-spec.md`; verdicts in `docs/architecture/<topic>-review-verdict.md`**: Stable layout lets workflow steps reference inputs/outputs by predictable paths. (scope: Repo-wide doc convention.)
- **New commits, not amends, after CI/hook failures**: Pre-commit hook failure means the commit didn't happen; amending modifies the previous commit and can lose work. (scope: All PR-feedback follow-ups (e.g., 63fddb0, 1cd3e23 on PR #87).)
- **Verification-based step completion preferred over legacy `STEP_COMPLETE` markers**: Newer workflows show `verification-based completion` with signal counts and exit=0; older ones still use marker-based, which is noisier and easier to fake. (scope: Agent Relay workflow runners — gradually migrating off marker-based.)
- **Workspace packages re-export public surface narrowly; runtime-policy and similar substrates are subpath exports**: Premature top-level exports broke CI on PR #86 (runtime-policy). (scope: `packages/harness`, `packages/telemetry`, `packages/evals`.)
- **Author + dry-run workflows; do NOT execute them**: User explicitly owns execution per saved feedback memory. (scope: All Agent Relay workflow work in this repo.)
- **Self-reflection docs after each agent role (`*-executor-reflection.md`, `*-fresh-eyes-reflection.md`, `*-claude-reflection.md`, `*-validation-reflection.md`)**: Captures rationale and follow-ups that would otherwise be lost in PR descriptions. (scope: Substrate and v1 workflows.)

## Lessons Learned
- Don't export new substrate surface from package roots until it's exercised end-to-end (PR #86 CI failed because runtime-policy was exported from `@agent-assistant/harness` root before the workspace build order accommodated it.) - Add new substrates as subpath exports first; promote to root only after build, tests, and downstream consumers are green.
- String-keyed counter maps leak in long-lived harnesses (CodeRabbit's second pass on PR #87 caught that the child counter map retained parent turn entries indefinitely.) - Use WeakMap, bounded LRU, or explicit GC hooks for any per-turn/per-trace bookkeeping that lives in a long-running process.
- Direct-context fallback must prefer the child identifier, not the parent (Trace propagation in nested-subagent-runner was preferring parentTraceId over childTraceId in the direct fallback path, breaking trace continuity.) - In nested-runner code, default to the most-specific identifier first; only fall back up the chain when the child value is genuinely absent.
- Publish workflows must respect dependency-aware build order (VFS publish broke because the matrix included vfs but the build order omitted it, so artifact upload tried to copy `packages/vfs/dist` before it existed.) - Keep publish-build matrices and dependency-order arrays in lockstep; add CI validation for new packages.
- Workflow-generated dirty files leak into PRs if not excluded (Substrate workflow runs left `.trajectories/active/*` and `tmp/` files; these had to be kept out of the runtime-policy CI fix commit.) - Stage explicit files (not `git add .`); add `.trajectories/active/` and `tmp/` to gitignore or pre-commit checks.
- Marker-based completion is noisy and unreliable (Older workflow chapters show `STEP_COMPLETE` markers tangled with terminal control codes (`>7u`, `╭───╮`), making findings hard to parse.) - Migrate remaining workflows to verification-based completion with structured signals.
- Agent self-reflection captures load-bearing context that PR descriptions miss (Substrate workflow produced four reflection docs per slice; these surfaced follow-up scope (e.g., runtime-policy export split) that wouldn't fit a PR body.) - Keep authoring reflection docs even when they feel redundant — they're the primary record of why a slice was bounded the way it was.
